# 正式服客户端验收

状态：0.7.0 尚未执行游戏内验收。核对基线为 `12.1.5 (70783)` 的 UI 源码，实际客户端可能不同。记录日期、地区、客户端版本、`GetBuildInfo()` 接口号、分辨率、UI 缩放、职业、场景和其他已启用插件。测试前备份账号 SavedVariables，开启游戏的脚本错误显示。

## 首次加载

1. 只启用 LumaUI，确认插件列表版本、登录提示、设置入口正常；`/luma status` 没有错误。
2. 运行诊断页应包含“原生界面接管”段：正在运行的替代组件各一行，写明隐藏或保留了哪些原生框体；部件缺失时同一行列出缺少的部件（例如 aura API 缺失时单位框体保留原生框体）。停用组件后该行消失。
3. 检查中文字体无缺字、标签不换行、窗口不越界；验证 1920×1080、2560×1440 和超宽屏，以及游戏 UI 缩放和插件 70% / 100% / 150% 缩放。
4. 逐项启用、停用所有模块，重复三轮；观察无重复面板、重复定时器或错误刷屏。
5. 布局编辑移动信息条、经验条和已打开的背包窗口；Esc 完成，重载后位置保留，改变缩放和窗口尺寸仍可找到面板。

## 配置方案

创建空方案、复制当前方案、修改外观并来回切换；角色切换后各自选择仍在。删除其他角色正在使用的方案后，应回退到剩余方案。最后一个方案不可删除。重置当前方案需要再次点击确认。检查损坏字段不会引发加载错误。

## 主题与表面角色（0.15.0，VIS-05）

1. 暗场景与亮场景各看一遍：设置窗口、嵌入的导航区、按钮应是三种可区分的表面（窗口近不透明并带细边、内嵌区无色边只有轻微明度差、按钮最亮且带细边）；不应出现“每一行都有一圈亮框”。
2. HUD 承托（底部信息带、经验条、动作条面板）应比窗口更透，让场景透出；聊天背景在阅读时保持可读、输入时更实；不要让窗口、HUD 和聊天共用同一个不透明度。
3. 物理像素：分别在 100%、150%、200% 的 UI 缩放下截图放大检查设置窗口与按钮的细边，应为 1 个屏幕像素而不是 2 像素；修改 UI 缩放后打开设置或重载，细边应重新对齐；确认插件没有改写 `UIParent` 的缩放。
4. 嵌入区使用新生成的 `Media/inset.tga`；不应出现缺失贴图的绿色/白色占位方块，贴图路径大小写与 TGA 透明边正常。
5. 切换强调色（珍珠/青湾/琥珀）后，已缓存的设置窗口、导航选中线、按钮、动作条面板与聊天背景应立即更新，组件不应被重新启用或闪断。
6. 旧存档兼容：只有旧 `opacity` 字段的存档登录后，窗口/HUD/聊天使用新的默认值（0.92/0.80/0.82/0.90），旧值不被改写；更高版本的只读存档仍不写入。旧“面板透明度”滑块仍作用于背包、银行、提示框、小地图等尚未迁移的兼容面板（窗口/HUD/聊天的可见设置入口留到 VIS-08）。
7. 资源可复现：`python tools/make-media.py --output <临时目录>` 生成的 panel/bar/rule/glow 与发行文件逐像素一致，`inset.tga` 可重复生成；新增贴图会随 `Media/` 自动进入发行包。

## 动效与生命周期（0.15.0，VIS-06）

1. 打开设置窗口：应约 180 毫秒淡入，且窗口立即出现（可见性不等待动画）；关闭按钮约 130 毫秒淡出后才消失。
2. 中途反向：淡出时再按一次打开，应从当前透明度接续淡入，不出现闪断或从头开始；快速连续开关 50 次后，最终状态与最后一次意图一致，无卡在半透明的窗口。
3. 关闭按钮、`/luma` 和 Launcher 触发淡出，结束后隐藏；游戏的 Esc 路径直接隐藏并执行同一清理。检查淡出期间的点击与焦点，确认隐藏后不再拦截操作。
4. 切页：新页约 160 毫秒淡入，离开的页在隐藏前落定；连续快速切页 50 次后页面内容、选中线与滚动位置正确，无旧回调导致的错页。
5. 关闭外观页“窗口过渡”后：所有窗口立即出现/消失，无需重载；再开启后恢复过渡。当前“减少动态效果”只有配置字段（设置页入口在 VIS-08 之前未提供），验收时可临时用配置验证立即落定。
6. 淡入淡出途中切换配置方案或强调色：应直接到终态（窗口要么完全可见并重绘、要么已关闭），不残留中间透明度。
7. 空闲性能：打开再关闭背包/银行/设置后约 1 秒内不应再有过渡任务或驱动计时器；长时间挂机不新增周期性 ticker（血量、施法、冷却本轮未接入动效，必须保持即时）。
8. 战斗内开关设置或停用背包/银行：只应有 alpha 等装饰变化，无 `ADDON_ACTION_BLOCKED`，不修改受保护框体的几何。
9. 录屏：窗口打开、关闭、中途反向、切页各一段，与截图一起保存到本地记录；缺录屏时只记代码完成，不写“动效已验收”。

## 通用控件（0.15.0，VIS-07）

1. 开关行：右侧轨道与滑块随开关移动，点击整行切换一次并立即显示最终状态；禁用时外观变暗、无边框、点击无效。
2. 导航：选中项保持强调色边、强调文字与左侧强调条；鼠标进入、离开、快速切页后选中项不丢失（R03 回归）；切页后旧项回到普通状态。
3. 输入框：获得焦点时边框变为强调色；输入空名称或含 `|`、控制字符等非法字符时边框变为警示色，创建/复制按钮同时禁用且点击无效；中文输入法组合输入、粘贴超长文本、Esc/Enter 退出焦点均正常，退出后不残留强调边。
4. 滑条：拖动时数值标签跟随、配置只在松开鼠标时提交一次；滚轮每格提交一次；超出范围自动夹取；用程序刷新（切方案）不回写配置。
5. 配置页：当前方案行的“切换”为禁用态；只剩一个方案时“删除”为禁用态；禁用项点击无反应且不刷错误。
6. 滚动区：组件页/布局页/诊断页内容超出视口时出现自绘滚动条，拖动与滚轮可滚动、到顶/到底夹取；内容变短后滚动条范围收敛，不残留可拖动的空滚动条。
7. 按钮：悬停有细边与轻微底色变化，按下有明度变化，松开恢复；主要操作（创建/复制等）使用强调色；关闭按钮保持紧凑但可点。
8. 回调异常隔离：任一控件回调报错应只在 `/luma status` 记录（`controls/click`），页面其他控件与页面本身继续可用；正式包不包含人为抛错。
9. 逐状态截图：普通/悬停/按下/选中/禁用/焦点各一张，另录一段快速点击与拖动的短录屏；在 100% 与 150% UI 缩放下检查点击区域与文字截断。

## 设置窗口样板（0.15.0，VIS-08）

1. 头部：标题与版本同一行、说明一行、强调细线一行；内容起点比旧版更高，右上角关闭按钮可点且不压住标题；中文说明在 760 宽度内换行合理。
2. 外观页：六个分组（尺寸/动效/透明度/强调色与提示/布局/兼容）在暗、亮场景下都能分清；页面可滚动，长说明不越界；窗口/HUD/聊天透明度滑块拖动时值标签跟随、松开才保存；减少动态效果开启后窗口立即到终态。
3. 导航：选中项保持强调边、强调文字与左侧强调条；悬停、离开、快速切页后不丢失；切页时新页淡入、旧页落定。
4. 组件页：开关与运行状态仍按行显示；出现失败/不支持/依赖未满足的组件时底部显示“N 个组件需要关注”和“打开诊断”，点击跳转诊断页；全部正常时显示“已启用的组件都在运行”。
5. 诊断页：三个段可折叠/展开（组件状态、原生接管、会话错误），展开/收起有过渡，错误段标题显示当前错误数；折叠后下方段落上移，滚动范围随之更新；清除错误按钮有效。
6. 布局页：说明、预设和面板列表应作为一页滚动，长中文/英文说明及重叠提示不遮住控件；全部注册项都能滚动到达，切页后保留滚动位置。每行“移动”进入移动模式；只读存档时移动/重置/编辑模式与行按钮禁用。
7. 配置页：创建/复制/切换/删除/翻页/重置可用；输入非法名时创建禁用；当前方案不可切换、最后一个方案不可删除；只读存档显示提示并禁用全部写操作。
8. 关闭：关闭按钮、`/luma`、Launcher 触发淡出，Esc 由游戏直接隐藏；四条路径都应清理焦点。淡出期间再次打开从当前透明度接续，不会被旧回调隐藏。
9. 稳定性：窗口启闭 100 次、快速切页 50 次后对象数量与活动任务稳定；每页滚动位置独立保留。
10. 分辨率与缩放：1920×1080、2560×1440 与 100%/150% UI 缩放下检查字号、行距、边缘、焦点线与点击区域；原生 + LumaUI 与完整插件组合各一张截图，暗/亮各一组，并录窗口启闭与切页。缺少截图/录屏时只记代码完成，不写“视觉验收通过”。

## 动作按钮样板（0.15.0，VIS-09，默认关闭）

本卡只覆盖主动作条；其它条、微型菜单、背包按钮、额外动作、载具与飞出按钮不在范围内。

1. 同一根主动作条的前后截图与 10 秒录屏：图标应裁切到统一内边距，按钮四周只有 1 像素边与自有底色；空位仍是干净的空槽。
2. 键位：绑定新键、切换游戏手柄、重载后 HotKey 仍显示正确且不被裁切；堆叠/充能时 Count 字号为 12 号并保持右下角。
3. 拖入/拖出、技能替换、宏、物品：按钮仍可正常拖放与替换，不出现重复边框或悬空装饰；拖放过程中原生反馈可见。
4. 状态：冷却/GCD、充能、触发高亮（SpellHighlight/Flash/NewAction）、按下、选中、超距、不可用逐项截图；这些状态必须保持原生表现，不被自有边遮挡。
5. 战斗：战斗内所有按钮可点击施法、无 `ADDON_ACTION_BLOCKED`；战斗内切换组件只在脱战后应用。
6. 职业分页、姿态、潜行、载具、额外动作与飞出按钮：本样板不改这些机制，但需确认同一根条在形态切换后仍对齐；任何异常先关闭组件。
7. 编辑模式：移动或缩放该条后，自有底色与边跟随按钮、不漂移；停用组件后不残留边框，按钮恢复原生。
8. 与 BarTender 等动作条插件共存：本样板只作用于暴雪主条；若冲突，关闭本组件而不是隐藏或改写他人按钮。
9. 100%/150% UI 缩放下 1 像素边与字体的观感；暗/亮场景各一组；缺截图/录屏时只记代码完成，不写“按钮样板已通过”。

## 布局组与预设（0.15.0，VIS-10）

1. 小队：布局页只有“小队整组”一项；移动整组时四个成员一起移动、相对间距不变；缩放变化后成员随容器缩放。战斗中进入编辑立即退出，不保存半成品。
2. 顶部信息：信息条与经验条合并为“顶部信息”一项；移动后两者相对位置不变。停用/启用其中一个组件后，组的布局仍正确。
3. 团队：仍是一行“团队框体”，尺寸随小队列数变化时左上角保持不动。
4. 旧存档：升级前单独移动过的小队成员或信息条，升级后视觉位置不变；布局页不出现成员行。切换配置方案后，成员偏移按该方案保存的值恢复。
5. 16:9 预设：点“预览”只出现轮廓、真实面板不动；“应用预设”后才写入当前方案并可立即看到结果；“撤销预设”恢复应用前的位置；切换方案或重载后预览不残留。
6. 只读存档：布局页的预设按钮与组拖动都不可用，存档不被写入。
7. 战斗中：应用预设只在脱战后生效；编辑模式在进入战斗时立即退出。
8. 屏幕：1080p、1440p 与宽屏下，组落点与预览轮廓一致；改变 UI 缩放或分辨率后位置仍可找回，UIParent 全局缩放未被改写。
9. 第三方占位（如手动创建）：只在布局编辑时显示轮廓，不移动、不隐藏、不影响未知插件框体；退出编辑即隐藏。
10. 与其他 UI 插件共存：只移动 LumaUI 自己的组；若出现错位，退出编辑后重置位置并记录框体归属。
11. 战斗布局预览应显示实测的受管动作区轮廓：宽度和分行高度来自当前 1-3 动作条，缺失的条使轮廓缩小并在标签后显示“估算”，不再使用固定的两排 12 格。红框提示轮廓重叠或越界。预览/预设只移动 LumaUI 轮廓；动作条 1-3 的实际位置由“动作条”组件按同一中央几何接管。记录实际动作区宽度与左右边界（动作条和预设使用）；单位框另读可见冷却图标块宽度，见 002 的 `/luma unit`；底部基线由 004 的底带保证至少高于信息带上沿 8 UI 单位，本轮只在模拟中验证。

## 日常组件

检查金钱与区域事件、网络延迟、时钟；经验条检查升级、关闭经验获取、休息奖励和满级隐藏。分别追踪普通声望、友谊、名望和巅峰声望，对照原生进度与奖励待领取状态；切换追踪后应及时更新，不可读取时保留原生条。

### 信息条与经验条悬停

1. 悬停区域文字，确认提示框显示当前区域、子区域和坐标；换区域、进副本和载具时坐标跟随。
2. 悬停时间，确认显示本周已保存的团队副本、难度和重置倒计时；延长锁定的副本应带“已延长”标记，没有记录时显示“本周没有已保存的团队副本进度”。世界首领单独列出。
3. 悬停帧数/延迟，确认显示当前 FPS、本地与世界延迟。
4. 悬停金币，确认列出本账号已记录角色、当前角色标记、合计和战团银行余额；首次登录其他角色后，该角色需再登录一次才会出现在列表中。提示框末行应说明客户端无法读取其他子账号的金币。
5. 悬停经验条，确认显示当前/上限、完成百分比、剩余经验和休息奖励；满级或关闭经验获取时不显示。
6. 鼠标移开后提示框应立即消失，不与原生物品提示冲突；悬停各段时不应触发游戏报错。

### 底部信息带（004）

1. 默认登录与 `/reload` 后，信息带应贴住屏幕底边并横贯全宽，左右各留约 12 UI 单位内边距，顶部细线与游戏画面相接；不再出现左右内收或底部悬空。记录窗口比例与客户端 UI 缩放。
2. 九个读数从左到右为金币、耐久、FPS/延迟、背包、区域、公会/好友、邮件、坐标与时间，区域保持在画面中央；分隔线间距均匀。金币、时钟、延迟等读数变化时字段位置不应跳动。
3. 中文大额金币、较长的区域名和背包分母应完整显示；若仍被截断，记录字段、实际宽度与当时的窗口/缩放，再调整最小宽度而不是读取文本实时计算。
4. 应用 16:9 预设后信息带仍贴底；手动拖动并保存后重载保持；重置位置后回到贴底默认。改变分辨率、窗口尺寸或客户端 UI 缩放时，宽度与贴底位置应即时跟随，已保存的手动位置不被覆盖。
5. 把“面板缩放”调离 1.0，确认信息带随比例放大但左右边缘不越出屏幕，读数不被裁切。
6. 窗口窄于 1200 UI 单位时进入紧凑模式：只保留区域与时间（时钟选择底带时），其余通过整条悬停汇总；恢复宽窗后回到九段，不残留遮挡或空段。
7. 鼠标悬停各分段仍显示原提示；信息带空白处不截获鼠标，不挡住聊天、动作条与右下原生按钮。战斗中改变窗口尺寸时只排队的组件不受影响。
8. 停用“信息条”组件后，信息带与悬停释放，动作区、聊天和原生快捷入口保持可用；重新启用后恢复贴底。
9. 用 `/fstack` 记录原生微型菜单、背包按钮和右下快捷键的归属；本轮不移动未知原生或第三方控件，若与信息带重叠，记录对象名和游戏编辑模式中的可用摆法。

### 聊天

1. 主聊天窗口显示时背景贴合；移动、拉伸、隐藏/显示主窗口时跟随。

仍未解决、需要下一轮实机数据：

### 014 容器接管（2026-11-25，模拟通过，待客户端验证）

开关：设置 →「容器」→「接管背包与银行窗口」，或 `/luma bags takeover`；写入当前方案，默认关闭。开启时会同时启用银行组件（否则银行仍由客户端绘制）。

1. 按 B：客户端背包不应出现，LumaUI 背包约 160 ms 淡入；再按 B 应从当前透明度淡出并在结束前不响应点击；开合途中连续按键可反向。听到客户端背包的开/关音效属于预期（客户端窗口先显示再被隐藏，同一帧内完成，看不到闪烁）。
2. 点原生背包条上的单个背包按钮：应打开 LumaUI 背包（而不是对应容器框）。若之后又安装其它背包插件并接管这些入口：它应优先，且不得出现两个窗口——这是设计行为（包装而非改写），记录实际表现。
3. 邮箱、商人、银行打开时客户端会调用「打开全部背包」：应只看到 LumaUI 背包；若看到客户端容器或两个窗口，记录当时的 `IsAnyBagOpen()` 返回值与插件列表。
4. 银行：站到银行 NPC 打开银行，原生银行窗口应不可见且点不到，LumaUI 银行窗口出现并列出角色/战团银行页签；本窗口的 ×、Esc、以及直接走开都应结束会话，之后原生 `BankFrame` 再次打开时透明度和可点击性恢复到打开前。若原生银行残留一块可点的隐形区域，记录坐标与 `/fstack` 归属。
5. 关掉开关：原生 B 键与原生银行应立即恢复，不需要重载；`/luma ownership` 的 `inventory.entry` 从 `owned` 变回 `native`（原因为 `option-off`）。
6. 只读存档或战斗中切换开关：应拒绝写入并提示，不留下只装了一半的包装函数；`/reload` 后原生入口仍可用。

### 014 中央 HUD：接管客户端冷却查看器（模拟通过，待客户端验证）

规则：某组**正在绘制**（owned + enabled + 有法术 + 至少画出一个格子）时，隐藏客户端对应的 `EssentialCooldownViewer` / `UtilityCooldownViewer`；其余情况一律交回客户端。

1. 启用自有组并导入后：画面上应只剩 LumaUI 的一排图标，客户端那排消失；`/luma cds` 的 `native-viewers=` 应为 `essential=hidden,utility=hidden`（空组为 `kept`）。
2. 打开「冷却管理器」编辑界面：两个客户端查看器应立即出现（预览与拖动），退出编辑器后再次消失。进入编辑模式（Edit Mode）时应同样可见、可拖动。
3. 客户端重算可见性（进出战斗、切编辑模式布局、改 CDM 的可见性选项）后，不应出现客户端查看器短暂停留：允许同帧内的显示再隐藏，但不应看到一整帧的重复图标。
4. 把某组清空或关掉「启用自有技能组」：客户端查看器应立刻回来，LumaUI 那组消失。
5. 若玩家在 CDM 里把某组设为「隐藏」或关闭冷却管理器 cvar：本插件恢复时不强制显示，`/luma cds` 仍报 `kept`。
6. 导入：在 CDM 里调整顺序、删掉一项后 `/luma cds import essential`，LumaUI 的顺序应与 CDM 一致；`/luma cds` 的 `entries` 与 CDM 数量一致（装备槽等非法术条目会被跳过）。
7. 图标：导入后每个格子应显示技能图标（fileID 直接交给 `SetTexture`）。若仍有格子为空，`/luma cds` 会打印 `unresolved: n (id…)` —— 把这些 ID 记下来，说明该条目在客户端里查不到名字也查不到图标。
8. 追踪增益：默认随自有组一起隐藏（`buff-viewers=hide`）。关闭「同时隐藏追踪增益查看器」或 `/luma cds buffs` 后应立即回来；LumaUI 不绘制追踪增益，关掉后没有任何补偿显示属于预期。
9. 组里有条目但全部解析不出时：客户端那块应保留（不出现整块空白），`/luma cds` 的 `drawn=0` 且 `unresolved` 等于 `entries`。

### 014 中央 HUD 三组（重要 / 效能 / 增益，模拟通过，待客户端验证）
默认状态（014 后期）：`owned` 默认开、三组默认开启、每组 `auto` 跟随客户端冷却管理器；不需要 `/luma cds import` 之类的命令。旧存档通过一次性迁移开启一次（`migrations.cooldownGroupsDefault`），之后仍可在设置里关掉。


结构与客户端冷却管理器一一对应，每组独立：尺寸、间距、每行数量、横排/纵列、位置、导入与排序。

1. 布局页会列出三个组（重要技能组 / 功能技能组 / 追踪增益组）。分别调大小与间距，只有该组变化；在 `/luma edit` 里分别拖动，重载后各自位置保留；两组重叠时 `/luma hud` 报 overlap。
2. `/luma cds import essential|utility|buffs`，`/luma cds` 的 `entries` 应与 CDM 里该分类的可见条目数一致；在 CDM 里拖动顺序后再导入，顺序应跟随。
3. 追踪增益：给自己一个已跟踪的 buff → 图标、层数、剩余时间出现；buff 消失 → 该格消失；一个都不在时整块收起（不留空洞），客户端增益查看器此时应恢复（我们没东西可显示）。
4. 重要/功能：带 proc 改图标的技能（例如某些触发替换）应跟随客户端显示 override 图标；受限冷却保留图标、不显示计时。
5. 追踪增益组的独立开关「同时隐藏追踪增益查看器」默认开；关掉或 `/luma cds buffs` 后客户端增益查看器立刻回来，且我们的增益组仍照常绘制（会有两份）。
6. 三个组都为空但 `owned` 打开：客户端的重要/功能查看器都不显示（等价于“接管”），追踪增益查看器**仍然显示**（我们的增益组没内容时不抢），`/luma cds` 打印三组 `entries=0`。

1. **U1 解锁**：标题栏首次解锁（未选中）时所有手柄 alpha 为 1，不应出现 Lua 错误；选一个手柄后其余为 0.65；用动作条页选「动作条 6」再点「定位」，应直接选中该条。Esc、进战、切方案后不再有网格、工具栏或草稿。

9. **S1 设置**：中/英文各打开动作条、单位、冷却、聊天页；常用控件应首屏可见，状态是一句本地化短句；技术归属只在诊断页。100% 与 150% 缩放下控件名、数值、滚动条都应可读。
