# LumaUI

面向《魔兽世界》正式服的独立界面插件，当前版本 **0.15.0 预览版**。使用游戏内置纹理与自绘素材，没有第三方运行库依赖。以深蓝面板、青湾或琥珀强调色、轻量窗口过渡构成自己的视觉风格。

## 当前功能

| 功能 | 范围 |
| --- | --- |
| 设置窗口 | 外观、布局、组件、配置方案、运行诊断；紧凑标题、嵌入式导航与按用途分组；组件页显示真实运行状态并汇总需要关注的组件，诊断页分“组件状态/原生接管/其他插件/会话错误”四段可折叠（其他插件段列出本会话已安装与已加载的第三方插件，便于区分重叠归属）；窗口/HUD/聊天透明度与减少动效可直接调整，只读存档整体禁用并提示 |
| 布局控制 | 列出可移动的 LumaUI 面板、进入移动模式、重置位置、打开游戏编辑模式；小队与底部信息带按整组移动。16:9 和战斗布局支持预览、应用与撤销；战斗预览按实测的受管动作区尺寸绘制轮廓（原生条缺失时标注为估算），并标出轮廓重叠或越界；动作条 1-3 与冷却查看器读取同一份中央几何，其余原生条仍由游戏编辑模式调整 |
| 配置方案 | 账号共享、角色单独选择、创建、复制、切换、删除、重置 |
| 信息条 | 贴底全宽的底部单行分段带：金币、耐久、FPS/延迟、背包、区域、公会/好友、邮件、坐标与游戏时间按可用宽度分散，区域居中；默认完整显示，紧凑模式只保留区域与时间，悬停显示本周团本进度、网络延迟与账号金币统计 |
| 经验条 | 事件更新、经验或已追踪声望进度；悬停显示当前阶段进度，经验模式显示剩余经验与休息奖励；数据不可读时保留原生进度条 |
| 聊天 | 聊天窗口与输入区使用独立透明度，输入焦点带过渡；标签用金色下划线与文字表示选中，未读与悬停有独立状态，字体与行距可回退 |
| 小地图 | 方形遮罩、HUD 承托、细边与区域名条；区域名条宽度跟随地图并在长地名时截断；时钟/坐标默认由底部信息带显示，选择“小地图时钟”时恢复小读数；隐藏原生罗盘与顶部标题边框 |
| 任务 | 原生追踪器默认重排到小地图下方、右对齐并沿用地图列宽度，关闭组件或停用小地图时恢复原锚点；标题使用 Pearl 金色。任务面板默认关闭，可显式开启，提供折叠、追踪、筛选、任务物品按钮、组队同步、右键菜单与世界任务时限。面板有任务时只接替任务模块，场景、地下城、成就等仍由游戏显示；空筛选或与原生追踪器重叠时交还任务模块，停用后全部恢复。折叠、任务物品与世界任务尚待游戏内验收 |
| 提示框 | 主提示框、聊天链接提示与比较提示的单层表面与细描边，隐藏原生九宫格 |
| 背包 | 搜索、分页、分类筛选、拾取/使用/拖动、Shift 链接、整理、Ctrl 拆分堆叠 |
| 银行 | 只读浏览角色银行与战团银行，拾取/使用与背包一致；`/luma bank` |
| 单位框体 | 默认开启并接管的玩家、目标、目标的目标、焦点、宠物框体；玩家与目标同宽并共享屏高 69% 的生命条顶边，对称围绕实测冷却图标块（不可读时用 300 UI 回退），动作条仍位于其下方，宠物与目标的目标用一半宽度的紧凑样式位于各自列内侧、焦点在目标上方；名字与生命百分比在上、18px 生命条与资源条在下并带深色边线，目标条带施法图标与计时，另有普通光环与目标标记；玩家施法仍用客户端中央施法条，只在布局编辑时预留原生位置轮廓；`/luma takeover` 可随时退回原生框体，替代功能尚待游戏内等价验收 |
| 小队框体 | 默认开启的 4 个安全按钮，包含名字、生命/能量、职责、状态和原生私有光环锚点；原生小队框体由组件隐藏并在关闭后恢复，尚待实际战斗验收 |
| 团队框体 | 默认关闭的最多 40 个安全按钮预览，按小队分列并带职责、状态、团队标记和原生私有光环锚点；原生团队框体和管理框保留，尚待实际战斗验收 |
| 角色窗口 | 默认关闭的自建窗口：装备槽、角色模型、属性、声望与货币；使用 `/luma char` 打开，顶栏可打开原生窗口，Esc 关闭；游戏角色快捷键与原生窗口保持独立 |
| 系统窗口皮肤 | 人物（换皮模式）、邮件、社交、法术书、NPC 对话/商人/任务的 LumaUI 外观；与自建角色窗口互斥 |
| 点击施法 | `/luma cc shift-left 法术名` 把法术绑定到 LumaUI 单位框体的组合键点击 |
| 动作条 | 默认开启：把 1、2、3 动作条按共享的动作区基线居中在底部信息带上方并向上堆叠，默认淡出隐藏，鼠标进入实测动作区时淡入；右侧/左侧与 5-7 号动作条停靠隐藏，宠物条、姿态条和所有按钮行为保持原生。冷却数字使用原生 Cooldown 引擎并居中显示，只调整字体、位置与可见性，不读取或计算冷却值 |
| 动作条面板 | 在原生动作条背后绘制 LumaUI 面板，并跟随动作条的淡入淡出透明度；按钮、键位、翻页保持原生 |
| 冷却管理器 | 把游戏自带的冷却管理器查看器（重要技能、功能技能、追踪增益的图标或条）统一放到实测动作区上方的居中堆叠里；已隐藏、为空或透明度为零的查看器保持客户端设置、不占行；追踪列表、冷却计时、发光与提示框仍由客户端负责，本组件只改位置，关闭组件即恢复原位置 |
| 动作按钮样板 | 默认关闭的单条样板：只给主动作条自带按钮做图标裁切、1 像素描边、自有底色与 LumaUI 键位/数量字体；点击、绑定、翻页、拖放、冷却/充能/触发等状态全部原生，其它动作条不受影响 |
| 姓名板 | 默认开启，把**目标姓名板**的血条重绘为 LumaUI 渐变并加 Pearl 底轨/细边；姓名板本身仍由游戏管理，可回退 |
| 战斗文本 | 只把游戏浮动战斗文本的字体与描边改为 LumaUI 风格，不读取也不生成任何数值 |
| 视觉素材 | 自绘 `Media/` 贴图（面板渐变、状态条明暗、渐隐条、辉光、嵌入区微渐变），由 `tools/make-media.py` 生成；主题提供窗口/嵌入区/按钮/HUD/聊天表面角色、标题/正文/标签/数值/次要文字语义、统一间距与按物理像素对齐的细边 |

原生组件在 LumaUI 组件关闭后自动恢复；所有接管都记录启用前状态并支持回退。设置窗口打开/关闭与切页使用可中断的过渡，切页带轻微位移；关闭“窗口过渡”或启用减少动态效果时立即落定，不留下半透明窗口；过渡只驱动 LumaUI 自有装饰，不读取或计算生命、施法、冷却数值。完整的姓名板系统、光环分类、战斗统计、首领计时与完整的系统窗口重做仍未实现。

## 安装与使用

将整个 `LumaUI` 目录放入游戏安装位置的 `_retail_/Interface/AddOns/`，确保结构是 `AddOns/LumaUI/LumaUI.toc`。也可以按 TOC 白名单打包：Windows 运行 `powershell -File tools/package.ps1`，macOS/Linux 运行 `tools/package.sh`，再把生成的 `dist/LumaUI-<版本>.zip` 解压到 `AddOns`。打包会包含 TOC 列出的 Lua、README、两份文档，以及 `Media/` 下的自绘贴图。

TOC 声明的接口为 `120100, 120105`，对应核对时的 `12.1.5 (70783)` UI 源码基线，**不表示已经在该构建完成游戏内测试**。通过 `/luma status` 检查实际客户端版本与接口号。

| 命令 | 用途 |
| --- | --- |
| `/luma` 或 `/lumaui` | 打开或关闭设置 |
| `/luma edit` | 开始或结束 LumaUI 面板移动，Esc 也可结束 |
| `/luma layout` | 打开布局控制页 |
| `/luma bags` | 打开或关闭背包浏览器 |
| `/luma bank` | 打开银行浏览器（需启用「银行」组件） |
| `/luma char` | 打开自建角色窗口（需启用「角色窗口」组件） |
| `/luma party` | 打印小队框体诊断信息 |
| `/luma raid` | 打印团队框体诊断信息 |
| `/luma bars` | 打印动作条归属只读报告：每条是否存在、显隐、屏幕坐标、是否处于默认位置与可见按钮数；动作条组件开启时，1-3 条的位置和淡入淡出由 LumaUI 管理，其余条仍由游戏编辑模式管理 |
| `/luma cc <组合键> <法术>` | 绑定点击施法，例如 `/luma cc shift-left 快速治疗`；`off`/`list`/`clear` |
| `/luma aura` | 光环行在「全部」与「只显示带可驱散学派的减益」之间切换（不判断角色自身的驱散能力） |
| `/luma status` | 打开运行诊断 |
| `/luma help` | 查看命令 |

战斗中修改设置会保存意图，在脱战后统一应用；受保护对象的创建与属性写入也在脱战队列中执行。未来版本的存档会以只读方式处理，避免旧版覆盖新数据。

## 开发与验证

运行环境使用 Lua 5.1 兼容语法。`node tools/verify.cjs` 检查加载清单与静态约束，安装外部解析器时同时检查 Lua 5.1 语法；`node tools/test.cjs` 运行行为测试（可用 `LUMA_LUA`、`LUMA_LUA_JS` 指定解释器）。

`tools/package.sh` 与 `tools/package.ps1` 使用同一份 TOC 白名单，并额外收录 `Media/` 下的自绘贴图；输出 `dist/LumaUI-<版本>.zip` 并打印 SHA-256，不包含 `agent_flow/`、`tests/` 或 `tools/`。

模拟测试只能检验逻辑与生命周期，不能证明游戏内布局、污染、秘密值传播或所有 API 版本都正确。正式游戏验收步骤见 [客户端验收](docs/IN_GAME_VALIDATION.md)，扩展方式见 [扩展接口](docs/EXTENSIONS.md)。本地评审和迭代资料保存在被忽略的 `agent_flow/` 中。
