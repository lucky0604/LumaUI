# LumaUI

面向《魔兽世界》正式服的独立界面插件，当前版本 **0.16.0 预览版**。使用游戏内置纹理与自绘素材，没有第三方运行库依赖。以深蓝面板、青湾或琥珀强调色、轻量窗口过渡构成自己的视觉风格。

## 当前功能

| 功能 | 范围 |
| --- | --- |
| 设置窗口 | 外观、布局、组件、配置方案、运行诊断；模块页改为“先选对象、再给该对象的真实控件”（动作条 1–8、单位框、冷却三组、聊天主窗），常态只显示一句本地化状态与常用数值，技术归属、英文键与证据等级集中在诊断页；窗口/HUD/聊天透明度与减少动效可直接调整，只读存档整体禁用并提示 |
| 布局控制 | 列出可移动的 LumaUI 面板、进入移动模式、重置位置、打开游戏编辑模式；小队与底部信息带按整组移动。16:9 和战斗布局支持预览、应用与撤销；战斗预览按实测的受管动作区尺寸绘制轮廓（原生条缺失时标注为估算），并标出轮廓重叠或越界；动作条 1–3 支持逐条移动、缩放和配置保存，默认堆叠的部分仍与冷却查看器共用中央几何 |
| 配置方案 | 账号共享、角色单独选择、创建、复制、切换、删除、重置 |
| 信息条 | 贴底全宽的底部单行分段带：金币、耐久、FPS/延迟、背包、区域、公会/好友、邮件、坐标与游戏时间按可用宽度分散，区域居中；默认完整显示，紧凑模式只保留区域与时间，悬停显示本周团本进度、网络延迟与账号金币统计 |
| 经验条 | 事件更新、经验或已追踪声望进度；悬停显示当前阶段进度，经验模式显示剩余经验与休息奖励；数据不可读时保留原生进度条 |
| 聊天 | 聊天窗口与输入区使用独立透明度，输入焦点带过渡；标签用金色下划线与文字表示选中，未读与悬停有独立状态，字体与行距可回退；开启自有消息区后，消息视口外另有 LumaUI 自有外壳（卡片底、窗口名、未读标题、分隔线），随客户端窗口移动/缩放，输入框、标签、路由、链接命中与审核仍是客户端的；`/luma chat` 提供显式的 320 × 140 UI 尺寸试验（记录原尺寸，再输入即恢复，战斗中拒绝；停用组件也会恢复） |
| 小地图 | 方形遮罩、HUD 承托、细边与区域名条；区域名条宽度跟随地图并在长地名时截断；时钟/坐标默认由底部信息带显示，选择“小地图时钟”时恢复小读数；隐藏原生罗盘与顶部标题边框。`···` 打开 LumaUI 自有抽屉（设置、背包、角色、移动、日历、世界地图），原生日历/追踪/第三方按钮位置不变 |
| 工具角 | 底带右侧、统计预留之上的单个「工具」入口（≥24×24 UI），打开一份共享菜单：设置、背包、角色、移动面板、日历、世界地图、游戏菜单，以及「展开原生工具条」。小地图右上角的 `···` 打开同一份菜单；工具角在屏时它让位，关闭工具角后仍可从这里进入。原生背包条（`BagsBar`）与微型菜单（`MicroMenu`）各自独立「平时收起 / 沿用客户端」，默认平时收起；收起走脱战队列并立即读回 `IsShown` 校验，拒写、第三方父级、编辑模式或展开期间交还并记录原因。`MicroMenuContainer`、队列眼、袋槽点击、拖换袋、右键菜单与键位都不改写；对这类 Edit Mode 系统帧用其记录的 `HideBase` 隐藏（直接 `Hide` 会被 `HideOverride` 重新显示）；对外部隐藏使用 Edit Mode 系统帧记录的 `HideBase`（直接 `Hide` 会被 `HideOverride` 重新显示）；`/luma tools [show\|hide\|bags <模式>\|micro <模式>]` 提供同一入口 |
| 任务 | 设置页可切换「任务面板挂在小地图下方」（手动摆放过则保留原位置，关闭后回默认）；原生追踪器默认重排到小地图下方、右对齐并沿用地图列宽度，关闭组件或停用小地图时恢复原锚点；标题使用 Pearl 金色。任务面板默认关闭，可显式开启，提供折叠、追踪、筛选、任务物品按钮、组队同步、右键菜单与世界任务时限。面板有任务时只接替任务模块，场景、地下城、成就等仍由游戏显示；空筛选或与原生追踪器重叠时交还任务模块，停用后全部恢复。折叠、任务物品与世界任务尚待游戏内验收 |
| 提示框 | 主提示框、聊天链接提示与比较提示的单层表面与细描边，隐藏原生九宫格 |
| 背包 | 搜索、分页、分类筛选、拾取/使用/拖动、Shift 链接、整理、Ctrl 拆分堆叠。设置 →「容器」里的「接管背包与银行窗口」（或 `/luma bags takeover`）开启后，B 键、原生背包条按钮与所有「打开全部背包」路径（银行、邮箱、商人）改为打开本窗口并隐藏客户端容器；关闭后立即恢复，无需重载。用的是包装而非改写：若另一个背包插件已经接管这些入口，它先运行且本插件不叠加窗口，也不会改写它的函数（本机现只安装 LumaUI，入口为客户端原函数，接管直接生效） |
| 银行 | 只读浏览角色银行与战团银行，拾取/使用与背包一致；`/luma bank`。接管开启时，银行会话期间原生 `BankFrame` 保持 `Show`（隐藏它会调用 `C_Bank.CloseBankFrame` 结束会话）但透明度 0、不可点击、内容面板隐藏，由本窗口代替；关闭本窗口即结束会话并把原生框体恢复成记录前的状态。开启接管会同时启用银行组件 |
| 单位框体 | 默认开启并接管的玩家、目标、目标的目标、焦点、宠物框体；玩家与目标同为 180 UI 宽，生命条顶边与实测的主技能行（重要/功能）上沿共线（无主行时回退到屏高 69%），对称围绕实测冷却图标块，动作条仍位于其下方，宠物与目标的目标用一半宽度的紧凑样式位于各自列内侧、焦点在目标上方；名字与生命百分比在上、18px 生命条与资源条在下并带深色边线，目标条带施法图标与计时，另有普通光环与目标标记；玩家施法仍用客户端中央施法条，只在布局编辑时预留原生位置轮廓；`/luma takeover` 可随时退回原生框体，替代功能尚待游戏内等价验收 |
| 小队框体 | 默认开启的 4 个安全按钮：32 单位紧凑行（职业图标、名字、8px 生命、2px 资源）加右侧预留列（职责、状态与五个原生私有光环锚点），四行约占屏高 12–15%；原生小队框体由组件隐藏并在关闭后恢复，尚待实际战斗验收 |
| 团队框体 | 默认关闭的最多 40 个安全按钮预览，按小队分列并带职责、状态、团队标记和原生私有光环锚点；原生团队框体和管理框保留，尚待实际战斗验收 |
| 角色窗口 | 默认关闭的自建窗口：装备槽、角色模型、属性、声望与货币；使用 `/luma char` 打开，顶栏可打开原生窗口，Esc 关闭；游戏角色快捷键与原生窗口保持独立 |
| 系统窗口皮肤 | 人物（换皮模式）、邮件、社交、法术书、NPC 对话/商人/任务的 LumaUI 外观；与自建角色窗口互斥 |
| 点击施法 | `/luma cc shift-left 法术名` 把法术绑定到 LumaUI 单位框体的组合键点击 |
| 动作条 | 默认开启：动作条 1–3 默认在信息带上方居中堆叠。使用「布局 → 移动面板」可逐条拖动，动作条页可按条设置 50%–150% 缩放。拖出堆叠的条独立记录位置：仍保留自己的行高，避免 HUD 冷却块随动作条移走而一起下坠，但不再参与中央内容宽度；指针落在哪一条就只唤醒那一条：命中按宿主自身的按钮矩形判定（`GetMouseFoci` → 宿主/按钮/飞出菜单父级 → 按钮矩形 → 宿主矩形兜底），不再使用共享大矩形或 22 UI 外扩；进入同一条内换格不闪，移到相邻条时旧条立即收起、只让新条淡入（≤0.15 秒），离开整组保留 0.20 秒宽限后于 ≤0.20 秒淡出；聊天、已注册布局窗口与设置窗口在前时不唤醒；编辑模式（客户端 Edit Mode 与 `/luma edit`）显露受管条，关闭即重算；客户端已隐藏的条不会被强制显示；减少动效或关闭动效时立即落定。每条可单独选「独立悬停 / 本条常显」（`ui.actionBarHover`，缺省独立悬停），每条宿主与当前透明度见 `/luma bars` 的 `hover` 行。**动作条 4–8（右/左/5–7）由客户端决定位置与显隐**（动作条页选中它们时会提示去客户端编辑模式关闭），升级后若曾被旧会话停靠，会按记录的父级/锚点归还一次；宠物条、姿态条、额外动作与区域技能只登记为布局占位与归属记录。动作条页对 2–8 号条提供按钮数、行数、按钮大小、间距与「始终/战斗中/脱战/隐藏」的显隐设置，写出前记录客户端原始尺寸与锚点，脱战经 `RegisterStateDriver` 交接、重置或停用后逐项还原；隐藏的按钮仍保留动作与按键。原生动作按钮的 Cooldown 对象与倒计时文本**完全不写**：12.x 的冷却更新会把 secret 起止时间传给 `SetCooldown`，任何插件对该对象的写入都会污染这次调用（实测报错 `Secret values are only allowed during untainted execution`），冷却数字保持客户端的原生字体与位置 |
| 动作条面板 | 在原生动作条背后绘制 LumaUI 面板，并跟随动作条的淡入淡出透明度；按钮、键位、翻页保持原生 |
| 冷却管理器 | 把游戏自带的冷却管理器查看器（重要技能、功能技能、追踪增益的图标或条）放到实测动作区上方的居中堆叠里；已保存的布局、客户端清单快照与即时计时分开保存：普通冷却、充能、触发与光环事件只刷新格子，不再清空清单；来源瞬断沿用同方案/专精下最近一次完整可读清单（诊断 `stale`），确认空表才清空，专精/装备/法术变化才重建；隐藏客户端查看器后回读 `IsShown/IsVisible/alpha`，只有真的不在屏幕上才发布 `active=owned`，拒写则收起自有层并记 `handover-hide-refused`；客户端时长对象（`GetSpellCooldownDuration`/`GetSpellChargeDuration`/`GetAuraDuration`）原样交给 `Cooldown:SetCooldownFromDurationObject`，受限对象不传递、不运算，并给可见图标套上可逆的 Pearl 皮肤：图标裁切、深色内衬、1 物理像素边线、计时与充能字体（原生计时、充能、发光、提示与点击不动；每个属性先记录再写，拒写即整帧回滚）。**默认按整块移动查看器**，不逐个改写客户端池化按钮的锚点——那会与客户端自己的重排互相覆盖。`/luma slots` 可选择逐图标槽位（重要 9、功能 7、短行居中、窄屏按整图标降容量）；该模式下若某查看器拒绝改锚则整行回退，若客户端连续三拍把图标改回原位则整组退回原生网格并只报告一次（`cooldownViewer/reanchor`）。`/luma status` 的 `skin=应用/总数` 与 `/luma hud` 每个查看器行的 `skin=` 说明哪些图标带皮肤、哪些保持原生 |
| 玩家资源轨 | 默认开启：在技能块上方画一条连续细资源轨（锚在已应用的主技能上沿 +6，追踪增益在预留间距外），职业确有第二资源时再叠一条；死亡骑士默认保留原生逐枚符文，`/luma runes` 可切换到 LumaUI 自有六段符文行，并把预留高度交给布局。数值直接交给客户端 StatusBar 绘制，不做比较、拼接或持久化，原生个人资源显示与施法条保持不变；稳定态零锚点写入 |
| 自有冷却组 | `/luma cds` 管理三组自有图标，一一对应客户端的冷却管理器：**重要技能**（Essential）、**功能技能**（Utility）、**追踪增益**（TrackedBuff）。每组有自己的尺寸、间距、每行数量与横排/纵列，各自是独立的布局条目，可在 `/luma edit` 里单独移动、缩放（跟随面板缩放），互不牵连；`import` 优先读冷却管理器设置数据源（玩家自己排好的顺序、被隐藏/未学会的条目按客户端规则过滤），把冷却条目映射成法术后追加，`add/remove` 显式编辑。重要/功能按客户端条目绘制：图标跟随 `overrideSpellID`／`overrideTooltipSpellID`（proc 改图标时同步），图标以 fileID 直接 `SetTexture`，受限冷却保留图标但不显示计时；追踪增益读玩家光环（`C_UnitAuras.GetPlayerAuraBySpellID`），图标、层数、剩余时间都来自光环，没有该光环时该格不画、整组没有激活项时整块收起。触发（proc）读 `C_SpellActivationOverlay`，格子状态环是 1 像素描边、proc 加粗到 2 像素。**三组默认接管：客户端对应查看器（重要/功能/追踪增益图标与条）会被隐藏并在客户端重算可见性后继续隐藏**；该组被刻意留空、组内条目全部解析不出、关闭自有组、停用组件，或你打开冷却管理器编辑器／进入编辑模式时立即恢复。不写入客户端设置；剩余重叠由 `/luma hud` 报告 |
| 自有玩家施法条 | `/luma cast` 显式开启后，在动作区下方绘制自有施法/引导/不可打断条（与姓名板施法共用状态语言）。原生施法条在实机等价验收前保持可见；受限施法隐藏自有条并保留原生 |
| 自有动作条 | `/luma ownedbars on` 用安全动作按钮绘制 1–3 条（动作 ID 1–12、61–72、49–60），支持列数/尺寸/间距与逐条位置；键位、翻页与载具仍由客户端原生条负责，停止或关闭后原生条恢复 |
| 控件归属 | `/luma ownership` 和诊断页列出每个控件的配置意图、当前显示者、证据等级与回退原因；玩家施法、目标施法、姓名板与光环各层分别报告，不用一个总开关替代证据 |
| 任务指示沿边 | 给客户端已画在 NPC 头顶的任务按钮加共用沿边动效；按钮的点击、位置与图标保持原生，构建若使用别的全局名则不接管 |
| 动作按钮样板 | 默认关闭的单条样板：只给主动作条自带按钮做图标裁切、1 像素描边、自有底色与 LumaUI 键位/数量字体；点击、绑定、翻页、拖放、冷却/充能/触发等状态全部原生，其它动作条不受影响 |
| 姓名板 | 默认开启自有层：每块可读的原生姓名板绘制 112 × 7 窄轨（目标 120 × 8 并带标记）、名字在左上、百分比在右上；名字按显示列裁切（中文占两列）。生命值受限时不读取数值：`UnitHealth`/`UnitHealthMax` 直接交给自有 StatusBar 的 `SetMinMaxValues`/`SetValue`，百分比走 `UnitHealthPercent` 进 `SetFormattedText`；写入被客户端拒绝时该块板退回原生显示并在诊断里写明原因。原生 selectedBorder、底板、非目标遮罩、血条与名字逐件记录、隐藏、回读，换目标、池复用、切模式或停用时逐件恢复。客户端仍是点击、世界定位、堆叠、光环与施法条的主人。`/luma plates direct` 切换受限生命值直绘（关闭则受限板留给原生），`/luma plates native` 在隐藏/保留原生部件间切换，`/luma plates owned` 关闭自有层后回到原生重绘装饰模式。 |
| 边缘光环 | 默认关闭（设置 → 资源）：玩家增益/减益各一行，显示图标、层数与剩余时间（仅有倒计时的光环才启动每秒刷新），悬停提示，脱战可右键取消增益。只在整份光环列表可读时才淡出原生 BuffFrame/DebuffFrame（任何受限条目都保留原生），中央冷却组已绘制的追踪光环不重复显示，私有光环仍走客户端锚点 |
| 自有聊天视图 | 默认关闭（设置 → 聊天）：逐窗口旁听客户端处理后的最终行并绘制自有滚动区（滚轮、Shift 翻页、阅读历史时“N 条新消息”），链接走原生 `SetItemRef`，输入框仍是客户端的；受限消息整段原样交给客户端，不读取不入历史。战斗日志窗口、已加载 Prat/Chatter 等聊天插件、钩子或视图构建失败时该窗口保持原生并记录原因。关闭开关即恢复原窗口，无需重载 |
| 统计窗口 | 默认关闭的统计窗口样板：只绘制 `app:SetDamageMeterProvider(fn)` 注册的数据源返回的纯数值行（名称、职业色、占比），受限数值整行丢弃；无数据源时只显示一行说明，右下预留区域仍归玩家自己的统计插件。`/luma meter` 开关 |
| 控件与动效 | 控件状态由一个模型推导（静息/悬停/按下/选中/禁用/焦点），悬停时四条边从各自中心生长的共用动效（`UI/EdgePulse.lua`）服务主要按钮与任务指示；停用或失焦立即撤销可见层与计时。设置窗口右上角有 `ESC` 入口打开客户端游戏菜单 |
| 战斗文本 | 只把游戏浮动战斗文本的字体与描边改为 LumaUI 风格，不读取也不生成任何数值 |
| 视觉素材 | 自绘 `Media/` 贴图（面板渐变、状态条明暗、渐隐条、辉光、嵌入区微渐变，以及 Pearl 哑光战斗填充 `combat-fill.tga` 与局部文字衬底 `hud-scrim.tga`），由 `tools/make-media.py` 生成；`tools/verify.cjs` 校验每张 TGA 的类型、尺寸、位深、alpha 与负载长度。主题提供窗口/嵌入区/按钮/HUD/聊天表面角色、标题/正文/标签/数值/次要文字语义、统一间距、按物理像素对齐的细边，以及战斗条/衬底/图标计时字体的显式角色 |

原生组件在 LumaUI 组件关闭后自动恢复；所有接管都记录启用前状态并支持回退。设置窗口打开/关闭与切页使用可中断的过渡，切页带轻微位移；关闭“窗口过渡”或启用减少动态效果时立即落定，不留下半透明窗口；过渡只驱动 LumaUI 自有装饰，不读取或计算生命、施法、冷却数值。015 新增：设置窗口按模块分页（总览、14 个模块页、配置方案，每个组件恰好归入一页）、Esc 菜单 LumaUI 入口、NPC 对话与任务按钮的轻量动效、画面内解锁模式（`/luma edit` 统一入口：网格、磁吸、逐组件定位、保存/取消）、画面内锚定（拖动时吸附其他组件，落点含锚定规则持久化）、逐模块可选接管开关（聊天视图、边缘光环、任务列挂地图下、底带避让右下、窄屏避让，全部默认关）、逐窗口/逐部件的显示归属诊断（`/luma ownership`）。016 新增：解锁检查器不再把布尔值传给 `SetAlpha`、进入流程整体可回滚并按真实布局 ID 定位；Esc 菜单整体换成 LumaUI 外观（自有卡片底与阴影、标题用 LumaUI 字体与强调色、三片红底与金属花纹压掉、按钮改为自有表面与三态字体、宽度与内边距重排），入口仍是客户端池化按钮，行为、快捷键、手柄焦点、禁用提示与命中全部保留；悬停描边从 0 沿边走到 1（停住不消失、离开从当前值反向、池化按钮按实例与世代失效），停用后按记录的宽度、内边距、边框/标题贴图、按钮贴图与字体逐项还原；动作条 4–8 不再被强制停靠，并提供逐条数量/行数/大小/间距/显隐；冷却组把已应用布局、清单快照、即时计时与真实归属分开，隐藏客户端查看器后回读有效可见性才发布归属；设置页按“对象 → 控件”重排，技术信息集中在诊断页；聊天自有外壳与任务挂载开关接入设置。012 新增的自有姓名板层默认绘制，但客户端单位框仍是点击、定位、光环与施法条的主人，健康受限时会整层退回原生；冷却组三组默认接管，符文与玩家施法条、自有动作条默认仍保留原生显示，需在游戏内逐项验证后再考虑进一步接管；`/luma ownership` 会分开显示意图、当前显示者与证据等级。敌方姓名板的施法/光环逐部件接管、自有动作条的键位/翻页/载具、官方统计会话字段、角色窗外壳与 NPC 对话自绘、系统窗口自有呈现仍未验收；中央技能区、资源轨、冷却皮肤、小队紧凑行、统计样板、边缘所有权报告均通过模拟与几何断言，仍需实机画面确认。顶部性能读数默认关闭（性能读数由底部信息带承担），可在组件页单独开启。

## 安装与使用

将整个 `LumaUI` 目录放入游戏安装位置的 `_retail_/Interface/AddOns/`，确保结构是 `AddOns/LumaUI/LumaUI.toc`。也可以按 TOC 白名单打包：Windows 运行 `powershell -File tools/package.ps1`，macOS/Linux 运行 `tools/package.sh`，再把生成的 `dist/LumaUI-<版本>.zip` 解压到 `AddOns`。打包会包含 TOC 列出的 Lua、README、两份文档，以及 `Media/` 下的自绘贴图。

TOC 声明的接口为 `120100, 120105`，对应核对时的 `12.1.5 (70783)` UI 源码基线，**不表示已经在该构建完成游戏内测试**。通过 `/luma status` 检查实际客户端版本与接口号。

| 命令 | 用途 |
| --- | --- |
| `/luma` 或 `/lumaui` | 打开或关闭设置 |
| `/luma edit` | 开始或结束 LumaUI 面板移动，Esc 也可结束 |
| `/luma layout` | 打开布局控制页 |
| `/luma bags` | 打开或关闭背包浏览器；`/luma bags takeover` 开关「接管背包与银行窗口」并写入方案 |
| `/luma bank` | 打开银行浏览器（需启用「银行」组件） |
| `/luma char` | 打开自建角色窗口（需启用「角色窗口」组件） |
| `/luma party` | 打印小队框体诊断信息 |
| `/luma raid` | 打印团队框体诊断信息 |
| `/luma bars` | 打印 8 条固定动作条 + 姿态/宠物/额外动作/区域技能的归属只读报告：条目编号、动作槽范围、显隐、透明度、屏幕坐标、默认位置、可见按钮数、`owner=intent/active`；1–3 条的位置与淡入淡出由 LumaUI 管理，4–8 条默认仍归客户端（设置了每一条布局后由 LumaUI 排列按钮，显隐交给客户端状态驱动）；末尾的 `hover <条> host=… alpha=… mode=…` 逐条给出当前宿主与透明度 |
| `/luma tools` | 原生工具条：无参数打印背包条与微型菜单的意图/状态/实际显隐；`show` / `hide` 暂时展开或收起原生条（战斗中拒绝并提示），`bags client\|collect`、`micro client\|collect` 分别把一条改为沿用客户端或平时收起 |
| `/luma cc <组合键> <法术>` | 绑定点击施法，例如 `/luma cc shift-left 快速治疗`；`off`/`list`/`clear` |
| `/luma aura` | 光环行在「全部」与「只显示带可驱散学派的减益」之间切换（不判断角色自身的驱散能力） |
| `/luma plates` | 姓名板报告：逐板清单（最多 5 条）给出 `class=hostile/friendly/neutral/unknown`、所有者、现代/旧字段状态、装饰与填充结果，汇总行 `plates: bases= readable= hostile= … painted= keptFill=`；本客户端是否在绘制姓名板与 `nameplateShowEnemies/Friends`。`/luma plates on`（或 `friends`/`off`）按玩家明确要求改写客户端姓名板开关；`/luma plates owned` 切换自有窄轨层，`/luma plates direct` 切换受限生命值直绘，`/luma plates native` 切换原生部件隐藏/保留，`/luma plates cast` 单独开启自有施法行 |
| `/luma hud` | 只读几何报告：动作区、已应用的主技能上沿与内容块、四个冷却查看器的矩形/图标块/皮肤计数、地图/追踪器/聊天（含 LumaUI 底板）/施法/额外动作候选矩形、`vis=` 有效可见性与所有权、重叠行；编辑模式下同一批矩形以描边导引显示 |
| `/luma dump` | 把运行诊断页文本、HUD 几何报告、控件归属表、冷却组交接状态与姓名板逐板汇总写入 `LumaUIDB.diagnostics`，用 `/reload` 或退出游戏落盘后可直接查看 SavedVariables 文件，无需复制聊天内容 |
| `/luma slots` | 开关冷却管理器的逐图标槽位（默认关闭，按整块移动查看器） |
| `/luma chat` | 开关聊天窗口的 320 × 140 UI 尺寸试验；`/luma chat <宽> <高>` 保存主聊天尺寸（240–600 × 100–400），`/luma chat reset` 清除；战斗中拒绝 |
| `/luma meter` | 开关统计窗口样板（需已注册数据源）；`/luma meter api` 只读列出当前客户端的 `C_DamageMeter` 函数 |
| `/luma cds [owned\|import\|add\|remove\|clear]` | 自有冷却组：开关显示、导入客户端该组清单、增删法术、清空；空组不绘制任何内容。布局页「中央 HUD」区有同样的「启用自有技能组」与「导入客户端顺序」入口；`/luma cds file` 把完整诊断写入 `LumaUIDB.reports.cooldownGroups` |
| `/luma cds layout <组> h\|v`、`max\|size\|gap <组> <数>`、`move <法术ID> <组> [位置]`、`reset <组>` | 冷却组横排/侧边纵列、每行数量、图标大小、间距、跨组移动与重置位置；布局页「中央 HUD」区提供同样的编辑，改动先预览，点「应用」才保存 |
| `/luma cast [status]` | 开关自有玩家施法条或打印两者状态；原生条在验收前保持可见 |
| `/luma runes` | 切换死亡骑士自有六段符文行与原生符文显示 |
| `/luma ownedbars [on\|off\|size N\|columns N]` | 自有安全动作条 1–3：显式开启、尺寸与列数；键位与翻页仍为原生 |
| `/luma ownership` | 控件归属只读表：意图、当前显示者、证据与回退原因；加 `file`（`/luma ownership file`）时同一份内容写入 `LumaUIDB.reports.ownership` |
| `/luma takeover party\|raid` | 分别切换小队/团队原生框体接管；团队等价性未验证 |
| `/luma status` | 打开运行诊断 |
| `/luma help` | 查看命令 |

战斗中修改设置会保存意图，在脱战后统一应用；受保护对象的创建与属性写入也在脱战队列中执行。未来版本的存档会以只读方式处理，避免旧版覆盖新数据。

## 开发与验证

运行环境使用 Lua 5.1 兼容语法。`node tools/verify.cjs` 检查加载清单与静态约束，安装外部解析器时同时检查 Lua 5.1 语法；`node tools/test.cjs` 运行行为测试（可用 `LUMA_LUA`、`LUMA_LUA_JS` 指定解释器）。

`tools/package.sh` 与 `tools/package.ps1` 使用同一份 TOC 白名单，并额外收录 `Media/` 下的自绘贴图；输出 `dist/LumaUI-<版本>.zip` 并打印 SHA-256，不包含 `agent_flow/`、`tests/` 或 `tools/`。

模拟测试只能检验逻辑与生命周期，不能证明游戏内布局、污染、秘密值传播或所有 API 版本都正确。正式游戏验收步骤见 [客户端验收](docs/IN_GAME_VALIDATION.md)，扩展方式见 [扩展接口](docs/EXTENSIONS.md)。本地评审和迭代资料保存在被忽略的 `agent_flow/` 中。
